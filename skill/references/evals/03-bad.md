So the approach I'd recommend for migrating authentication from server-side sessions to JWTs is a phased one, wherein we first introduce token issuance alongside the existing session cookie, which should take about 2 days, followed by updating the API middleware so that it accepts either credential, which is roughly 1 day, and then moving the client over, which is the largest piece at approximately 3 days given that the ORM-backed user store needs to be touched in a few places and the CDN cache rules have to be adjusted so that the Authorization header isn't stripped, and finally retiring the session table, which is about 1 day. The one thing that isn't without risk is that the roughly 1,200 active users will be logged out at cutover since their sessions can't be translated into tokens, although the whole change is gated behind the AUTH_JWT flag, so rolling back is simply a matter of flipping it off. I'd need you to decide on token lifetimes, and I'd suggest 15 minutes for the access token and 7 days for the refresh token, unless you'd rather something else.
